# {{ cookiecutter.project_slug }}

API automation test project generated by [project_gen](https://github.com/Sergey-Gureev/progect_gen).

## Project structure

```
clients/http/{service}/     # generated OpenAPI clients (do not edit manually)
fixtures/
    _coverage.py            # swagger coverage utilities
    config.py               # pytest config fixture (set_config)
    {service}.py            # API client fixtures per service — edit here to add auth
tests/
    {service}/{api}/{test}/
config/
    stg.yaml                # service base URLs per environment
    swagger-coverage-config-{service}.json
    telegram-notifier-config.ini
results/
    allure/                 # raw allure data (gitignored)
    swagger-coverage/       # temporary coverage input files (gitignored)
reports/
    specs/                  # downloaded swagger JSON specs
    coverage/               # swagger-coverage-report-{service}.html
```

## Setup

### 1. Install dependencies

```bash
poetry install --no-root
```

### 2. Fill in config/stg.yaml

```yaml
service:
  my_service: "https://api.example.com"
```

Add the correct base URL for each service. The file is preserved on repeated `project_gen generate` runs.

### 3. Add authentication

Open `fixtures/{service}.py` and set the correct auth header:

```python
api_client = service.ApiClient(
    configuration=configuration,
    header_name="Authorization",
    header_value="your-api-key-here",   # ← edit this
)
```

For token-based auth (login → token), create a helper in `helpers/` and call it inside the fixture before returning `api_client`.

### 4. Enable tests

Tests are generated with `@pytest.mark.skip`. Remove it for tests you want to run:

```python
# @pytest.mark.skip   ← comment out or delete
async def test_get_users(service_users_api: service.UsersApi) -> None:
    ...
```

## Running tests

```bash
# Run all tests
pytest tests/

# Run tests for a specific service
pytest tests/my_service/

# Run a single test
pytest tests/my_service/users_api/get_users/test_get_users.py

# Run with a specific environment config
pytest tests/ --env=prod
```

## Allure reports

### Local

```bash
# Open interactive report in browser (auto-refreshes)
allure serve results/allure

# Or generate static HTML
allure generate results/allure -o reports/allure --clean
allure open reports/allure
```

Install Allure CLI once (requires Java):

```bash
brew install allure     # macOS
# Other: https://allurereport.org/docs/install/
```

### CI (GitLab / TeamCity)

Raw allure data is saved to `results/allure/` as CI artifacts.
The CI pipeline generates the HTML report in a separate step and preserves history across runs.

See `.gitlab-ci.yml` for the full pipeline configuration.

## Swagger coverage reports

After running tests, coverage HTML reports are generated in `reports/coverage/`:

```
reports/coverage/swagger-coverage-report-{service}.html
```

Open them in a browser to see which endpoints are covered.

Coverage rules can be tuned per service in `config/swagger-coverage-config-{service}.json`.

## Adding a new service

1. Add a new `[[http]]` block to `testproject.toml`
2. Run `project_gen generate` — new client, fixtures, and tests are created; existing files are preserved
3. Fill in the new service URL in `config/stg.yaml`
4. Add auth in `fixtures/{new_service}.py`

## Known issues

### `models/json_any.py` deserialization errors

Some swagger specs generate a `models/json_any.py` that fails to deserialize complex nested objects.
If you see deserialization errors, open `clients/http/{service}/models/json_any.py` and add:

```python
"Dict[str, None]",  # catch-all for complex dictionaries
```
